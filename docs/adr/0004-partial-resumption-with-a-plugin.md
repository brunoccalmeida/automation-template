# 4. Partial resumption: distribute the shared harness as a Claude Code plugin

- **Status:** Accepted
- **Date:** 2026-11-17
- **Supersedes in part:** [ADR 0001](0001-use-copier.md) (the plugin was deferred) and [ADR 0003](0003-stack-agnostic-core-defines-contracts.md) (contracts bound through Copier variables), for the pieces the plugin carries

## Context

The template was paused on 2026-11-06 until a paid project, or a third project needing the same harness, showed what is common. The second trigger fired: [playwright-nextjs-e2e-ci](https://github.com/brunoccalmeida/playwright-nextjs-e2e-ci) carries the same harness as [playwright-qa-starter-kit](https://github.com/brunoccalmeida/playwright-qa-starter-kit), [uat-automation-framework](https://github.com/brunoccalmeida/uat-automation-framework) and this repository. The hand-made copies of `close-mission` and `reviewer` already differ in all four; `ship-pr` is identical only between the kit and the nextjs project ([INVENTORY.md](../INVENTORY.md#mission-a-the-four-versions-of-the-plugin-pieces)).

ADR 0001 deferred a Claude Code plugin until skills changed often enough for `copier update` to become a burden. The pieces that drift are exactly the ones a plugin carries (skills and agents), and they change more often than the rest of the harness: every project improves them in its own missions. Copier would also fix the drift, but it still lacks the evidence to template the rest (packs, CI, rules), and its own walking skeleton has ten missions ahead.

## Decision

**Resume only the plugin, now. Copier stays paused; ADRs 0001 to 0003 stay valid for everything else.**

1. **Scope:** the three automation projects above. Another project joins only by joint decision.
2. **One repository:** the plugin and its marketplace live here, next to the future Copier template. The marketplace lists the plugin by relative path (`./plugins/mission`), so cloning the repository brings both ([Create a marketplace](https://code.claude.com/docs/en/plugins/create-marketplace.md)).
3. **Names:** plugin `mission`, which prefixes every component: `/mission:close-mission`, `/mission:ship-pr`, `mission:reviewer` ([Create a plugin](https://code.claude.com/docs/en/plugins/create.md)). Component names stay self-describing, as in Anthropic's own plugins (`/feature-dev:feature-dev`), because the skill authoring guide warns against vague names ([Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#naming-conventions)). Marketplace `brunoccalmeida-plugins`: the docs ask for a name other authors are unlikely to pick, since a user cannot register two marketplaces with the same name, and a marketplace has no `renames` map, unlike a plugin ([Marketplace reference](https://code.claude.com/docs/en/plugins/marketplace-reference.md)). The GitHub handle makes it unique; the `-plugins` suffix follows Anthropic's own marketplaces.
4. **Contracts, not commands.** The plugin is one artifact with no per-project variables. Its pieces name the ADR 0003 contracts (`check`, `test`, `smoke`) plus `main-branch`, `gate` and `session-summary`, and each project declares the real value in a contract table in its always-loaded rules. This replaces, for the plugin's pieces, the Copier variables of ADR 0003. The table is always in context: subagents load the same `CLAUDE.md` hierarchy as the main session ([Subagents, What loads at startup](https://code.claude.com/docs/en/sub-agents.md)). The format is in [plugins/mission/README.md](../../plugins/mission/README.md).
5. **Extension point for the reviewer:** project-specific review checks go in `REVIEW.md` at the repository root, the file Anthropic's Code Review reads for review-only instructions ([Customize Code Review](https://code.claude.com/docs/en/code-review-customize.md)).
6. **What goes in the plugin:** `close-mission`, `ship-pr` (`disable-model-invocation: true`: merging is a human decision) and `reviewer`. **What stays in each project:** stack documentation skills, `permissions.deny` and hooks (the manifest has no field for permission rules: [Manifest reference](https://code.claude.com/docs/en/plugins/manifest-reference.md#fields)), and `CLAUDE.md` or Copilot instructions (Claude Code does not load a `CLAUDE.md` at the plugin root: [Plugin components](https://code.claude.com/docs/en/plugins/components.md#skills)).
7. **Versioning:** `version` is omitted, so each install resolves to the commit SHA it was installed from and an update moves it to the latest commit ([Plugin loading, Versions and updates](https://code.claude.com/docs/en/plugins/loading.md#versions-and-updates)). Auto-update, off by default for third-party marketplaces, stays off; projects update on purpose.
8. **Mission record:** the session summary holds state and the next mission only; the record of a mission (decisions, sources, how RED was seen, review findings) goes in the pull request body, which a squash merge configured with the pull request description writes into the main branch ([Configuring commit squashing](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/configuring-commit-squashing-for-pull-requests)). Three of the four copies kept a growing per-mission section in the summary; the UAT summary had grown cells of more than 1,200 characters, and a file read at the start of every chat costs context and adherence ([Memory](https://code.claude.com/docs/en/memory), under 200 lines; [Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents), the smallest set of high-signal tokens; [Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents), git history as the agent's memory).
9. **Validation gate:** CI validates the marketplace and every plugin on each pull request, failing on any error or warning except the missing `version`. The docs say to drop `--strict` when `version` is omitted ([Publish a plugin](https://code.claude.com/docs/en/plugins/publish.md#prepare-your-plugin-for-release)); this deviates on purpose. Without `--strict`, an agent or skill whose frontmatter block is missing passes with a warning and loads with every field ignored ([Plugin components, Frontmatter fields in plugin agents](https://code.claude.com/docs/en/plugins/components.md#frontmatter-fields-in-plugin-agents)), which would give the read-only reviewer every tool and let the model trigger `ship-pr`. The exception is one exact message, so a change in it fails the gate loudly.

## Alternatives

- **Copier now, for the whole harness:** fixes the drift but renders skills into every project, so a fix still needs `copier update` and a three-way merge per project, and it would start the paused template ten missions early.
- **One plugin per project, or plugin variables (`userConfig`):** brings back per-project copies of the same text, or a configuration dialog per machine, for values the project's rules already hold.
- **A separate repository for the marketplace:** one more repository to keep in step with the template that will reference it, with no benefit while one person owns both.

## Consequences

- The three pieces exist once. A fix reaches a project with `claude plugin update mission@brunoccalmeida-plugins`, reviewed first because auto-update is off.
- A reader of a skill sees `check`, not `npm run check`, and must find the value in the contract table: the cost ADR 0003 avoided with rendering. It is accepted because the table is always loaded, for both the main session and the reviewer.
- Every consuming project must declare the contract table, allow squash merging with the pull request description and auto-merge, and require the `gate` check in a ruleset. The kit pilots this first (Mission B, #15), then the UAT and the nextjs project (Mission C, #16).
- One update changes the behavior of every consuming project at once; the CI gate, the pilot, and manual updates limit the blast radius.
- This repository still runs its hand-made `close-mission` and `reviewer` until it adopts its own plugin (Mission D, #17).
- When Copier resumes, it no longer renders these skills: it renders the contract table into the generated project's rules and adds the marketplace to `.claude/settings.json`. Mission 2b (#4) shrinks accordingly.
